# DVC Workflow — NeuralDBG

## Overview

NeuralDBG uses [DVC](https://dvc.org) to version binary artifacts (images, datasets, model weights) separately from Git. Git tracks code; DVC tracks data.

The remote storage is hosted on **DagsHub**: `https://dagshub.com/P3niel/NeuralDBG`

---

## First-time Setup

### 1. Install dependencies

```bash
source .venv/bin/activate
pip install dvc dvc-http
```

Or via bootstrap:

```bash
make bootstrap
```

### 2. Configure your DagsHub token

Generate a personal access token at: DagsHub → User Settings → Tokens

```bash
dvc remote modify --local dagshub password <YOUR_DAGSHUB_TOKEN>
```

The token is stored in `.dvc/config.local` which is gitignored — it will never be committed.

---

## Daily Usage

### Pull artifacts after cloning or switching branches

```bash
dvc pull
```

### Track a new binary file

```bash
dvc add path/to/file.png
git add path/to/file.png.dvc .gitignore
git commit -m "chore(dvc): track file.png"
dvc push
```

### Push after generating new artifacts

```bash
dvc push
```

## Remote configuration

The DVC config (`.dvc/config`) contains two remotes:

| Remote | URL | Role |
|--------|-----|------|
| `dagshub` (default) | `https://dagshub.com/P3niel/NeuralDBG.dvc` | Shared remote for all collaborators |
| `local-storage` | `/home/kami/dvc-store/neuraldbg` | Local fallback (machine-specific) |

## Troubleshooting

**`dvc: command not found`** — activate the virtual environment first:
```bash
source .venv/bin/activate
```

**`401 Unauthorized` on push/pull** — your token is missing or expired:
```bash
dvc remote modify --local dagshub password <NEW_TOKEN>
```

**`dvc push` uploads nothing** — run `dvc status` to check if files are up to date.
