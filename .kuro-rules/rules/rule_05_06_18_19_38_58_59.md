# RULE 5: Testing Requirements
## Minimum Coverage: 60% - no exceptions
| Type | Target | Scope |
|------|--------|-------|
| Unit Tests | 70% of test budget | Individual functions/methods |
| Integration Tests | 20% of test budget | Component interactions |
| E2E Tests | 10% of test budget | Complete user flows |

## Run Commands
Python: pytest --cov=. --cov-report=term-missing
Rust: cargo test + cargo tarpaulin
Node/React: npm test -- --coverage

## Enforcement
IF coverage < 60%: STOP new features, write tests until 60%+ reached

# RULE 6: Security Scanning
## Required before every commit AND at each milestone

| Language | Commands |
|----------|----------|
| Python | bandit -r . && safety check |
| Rust | cargo audit && cargo clippy -- -D warnings |
| Node.js | npm audit --audit-level=high |

## Blockers: bandit HIGH, safety CRITICAL, cargo VULNERABILITY, npm HIGH/CRITICAL
## Enforcement: IF scan fails -> STOP commit, fix, re-run, DO NOT use --no-verify

## Milestone Security Gates
AT each milestone (10/25/50/75/90/95%):
1. Run full security scan (bandit + safety)
2. Document results in SESSION_SUMMARY.md
3. IF critical vulnerabilities found: BLOCK milestone completion
4. Update SECURITY.md with current audit status

## Security Milestone Deliverables
| Milestone | Required Security Deliverables |
|-----------|------------------------------|
| 10% | SECURITY.md exists with scope, .env in .gitignore, initial bandit baseline |
| 25% | Dependency audit (safety), secret scanning (git-secrets or similar) |
| 50% | CI/CD security gates configured (Bandit in GH Actions), container scan if Docker used |
| 75% | Advanced: SAST/DAST tools integrated, dependency vulnerabilities tracked |
| 90% | Full vulnerability remediation, security compliance checklist complete |
| 95% | Security sign-off document, penetration test summary (even if internal) |

## Security Label
Every security task MUST use label: "Security"

## Security Documentation Requirements
- SECURITY.md: Must exist at project root, updated at each milestone
- Must include: scope, tools used, scan frequency, vulnerability handling process
- Must list: known vulnerabilities, remediation plan, risk acceptance if any

# RULE 18: Regression Prevention
## After EVERY fix, feature, or refactor:
1. RUN full test suite (not just affected module)
2. CHECK: did previously passing tests now fail?
3. VERIFY: mocks match real production data structures
4. ENSURE: fake timers isolated and cleaned up per test
5. CONFIRM: no mock returns null when object/array expected

## Enforcement: IF regression detected -> STOP new work, fix immediately

# RULE 19: Strict Versioning (SemVer-Author)
## Format: v[Major].[Minor].[Patch]-kuro
## Tag at every validation milestone (10/25/50/75/90/95%)

## Versioning Gates - NEVER SKIPPED

| Gate | When | Check | Action if Fail |
|------|------|-------|----------------|
| Gate 1 | At milestone | Milestone reached? | Generate version tag immediately |
| Gate 2 | Before Tag | milestone_X_tasks.md exists | BLOCK tag, generate tasks first |
| Gate 3 | Before Tag | 5 tasks in Linear/GitHub | BLOCK tag, create issues first |
| Gate 4 | Before Tag | At least 1 task started/done | BLOCK tag, start work on task |
| Gate 5 | After Tag | Tag pushed to remote | Verify with `git fetch --tags` |

## Tag Command Template
```bash
# 10%: git tag -a v0.1.0-kuro -m "10% milestone - initial setup complete"
# 25%: git tag -a v0.2.0-kuro -m "25% milestone - core extraction working"
# 50%: git tag -a v0.5.0-kuro -m "50% milestone - MVP feature complete"
# 75%: git tag -a v0.7.5-kuro -m "75% milestone - beta ready"
# 90%: git tag -a v0.9.0-kuro -m "90% milestone - release candidate"
# 95%: git tag -a v0.9.5-kuro -m "95% milestone - pre-launch"
git push origin vX.Y.Z-kuro
```

## Version File Requirement
Every project MUST have a VERSION file at root:
```
MAJOR=0
MINOR=X
PATCH=Y
MILESTONE=25%
LAST_TAG=v0.X.Y-kuro
```

UPDATE VERSION file at every tag. This file is used by CI/CD to verify versioning.

## Automated Version Check
```bash
# Pre-tag hook (add to .git/hooks/pre-push)
source VERSION
CURRENT_TAG=$(git describe --tags --abbrev=0 2>/dev/null || echo "none")
if [ "$CURRENT_TAG" != "v${MAJOR}.${MINOR}.${PATCH}-kuro" ]; then
    echo "❌ VERSION file does not match git tags"
    echo "Expected: v${MAJOR}.${MINOR}.${PATCH}-kuro"
    echo "Found: $CURRENT_TAG"
    exit 1
fi
```

## Enforcement
IF milestone reached without tag: STOP, create tag immediately
IF tag pushed without milestone tasks: BLOCK merge to main (CI gate)
IF VERSION file out of sync: BLOCK deployment

# RULE 38: Mandatory Code Review After Commit
## Timing: AFTER commit -> review -> THEN continue
## Tools: CodeRabbit (preferred), Qode, GitHub PR, CodeClimate
## Review criteria: quality, security (R6), coverage (R5), regression risk (R18), docs

## Enforcement: IF no review after commit -> STOP, request review, wait for approval

# RULE 59: Integration & E2E Coverage >= 90%
## Minimum flows: happy path, error path, edge case path
## Tools: Playwright or Cypress (web), pytest with httpx (API)
## Enforcement: IF critical flows untested -> STOP before phase transition
